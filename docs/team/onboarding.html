Team Structure

The SC Chatbot project operates with three main user roles, each with different permissions and responsibilities:

Super Admin

  • Responsibilities: System-wide management, tenant onboarding, global settings
  • Access: Full system access across all tenants
  • Tools: Tenant management, API key management, analytics dashboard
  • Typical Users: Company founders, platform administrators

Tenant Admin

  • Responsibilities: Manage their own tenant, configure knowledge base, set up tools
  • Access: Full access within their tenant
  • Tools: Knowledge upload, tool configuration, channel setup
  • Typical Users: SME business owners, customer service managers

Agent

  • Responsibilities: Handle customer conversations
  • Access: Limited to assigned tenant
  • Tools: Conversation viewer, manual responses, escalation workflows
  • Typical Users: Customer service representatives, support staff

Testing Requirements

  • Unit tests: Write pytest tests for all functions
  • Coverage: Maintain >70% coverage
  • Async tests: Use pytest-asyncio for async code
  • Integration tests: Test API endpoints

Commit Messages

  • Conventional commits: Use feat:, fix:, docs:
  • Descriptive: Explain what changed and why
  • Format: type(scope): description
# Good commit messages
feat(knowledge): add PDF parsing support
fix(chat): handle rate limit errors gracefully
docs(api): update /mcp/query endpoint documentation
test(tools): add unit tests for tool invocation
refactor(llm): optimize prompt caching strategy
chore(deps): bump fastapi from 0.100.0 to 0.104.0

Branch Workflow

  1. Create feature branch from main
  2. Make changes and write tests
  3. Update documentation
  4. Submit pull request to main
  5. Get code review and approval
  6. Merge to main
# Branch naming convention
# feat: new-feature-name (max 50 chars)
# fix: bug-fix-description
# docs: documentation-update
# test: add-tests-or-fix-tests
# refactor: code-structure-change
# chore: build-system-or-deps
# perf: performance-improvement
# ci: continuous-integration

Development Setup

Follow these steps to set up your development environment:

1. Install Prerequisites

  • Python 3.11+: python --version
  • Git: For version control
  • Make: For Makefile targets
  • Docker: For containerized development

2. Clone Repository

# Clone the repository
git clone git@github.com:di-hieu/e-business.git
cd e-business

# Create virtual environment
python3 -m venv venv
source venv/bin/activate  # Linux/Mac
# venv\Scripts\activate   # Windows

# Install dependencies
make install-dev

# Run tests
make test

3. Run Development Server

# Development mode with hot reload
make dev

# Or use Docker Compose
docker-compose up -d

# View logs
docker-compose logs -f

# Stop development
make stop

4. Configure Environment

# Copy example environment file
cp .env.example .env

# Edit with your credentials
vim .env

# Required variables:
# OPENAI_API_KEY=your_openai_api_key
# LITELLM_MODE=pass_through
# ZALO_CLIENT_ID=zalo_client_id
# ZALO_CLIENT_SECRET=zalo_client_secret

Code Review Process

All contributions go through a code review process:

Review Checklist

  • Code follows PEP 8 style
  • Tests cover new functionality
  • Documentation is updated
  • No sensitive data in code
  • Changes are minimal and focused

Review Guidelines

  • Be constructive and specific
  • Ask questions rather than make statements
  • Focus on code quality, not personal preference
  • Respectful and professional communication
💡 Tip: Small, focused PRs get reviewed faster. Breaking changes should be discussed before implementation.
