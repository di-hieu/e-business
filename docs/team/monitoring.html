Monitoring Overview

Monitoring is essential for maintaining a healthy, reliable AI chatbot platform. This guide covers metrics, logging, tracing, and alerting.

Infrastructure Monitoring

Production monitoring additions:

Prometheus Metrics

What it is: Open-source metrics collection and time-series database.

Why use it: Industry standard, powerful querying (PromQL), integrates with Grafana.

Metrics to expose:

  • http_requests_total: Total HTTP requests
  • chatbot_responses_total: Bot response count
  • llm_calls_total: LLM API calls
  • tool_calls_total: Function calls executed
  • response_time_seconds: API response time
  • error_rate_total: Error count by type

Grafana Dashboards

What it is: Visualization platform for metrics data.

Why use it: Create beautiful dashboards, alert on thresholds, share with team.

OpenTelemetry

What it is: Observability standard for collecting telemetry data.

Why use it: Distributed tracing, unified format, integrates with Prometheus.

Structured Logging

What it is: JSON-formatted logs for easy parsing.

Why use it: Better than plain text, queryable with ELK stack.

Metrics Implementation

Prometheus Metrics in FastAPI

# Install Prometheus client
pip install prometheus-client

# In FastAPI app.py
from fastapi import FastAPI
from prometheus_client import generate_latest, COLLECTORS

# Create app
app = FastAPI()

# Enable default collectors
# For production, be selective about which metrics to expose
# COLLECTORS = ["prometheus"]

# Custom metrics
from prometheus_client import Counter, Histogram, Gauge

chatbot_responses = Counter(
    "chatbot_responses_total",
    "Total chatbot responses generated",
    labels=["status", "channel"]
)

response_time = Histogram(
    "chatbot_response_time_seconds",
    "Response time for chatbot in seconds",
    buckets=[0.1, 0.5, 1.0, 2.0, 5.0, 10.0]
)

llm_calls = Counter(
    "llm_calls_total",
    "Total LLM API calls",
    labels=["provider", "model"]
)

tool_calls = Counter(
    "tool_calls_total",
    "Total tool function calls",
    labels=["tool_name", "result"]
)

# Health endpoint
@app.get("/health")
async def health_check():
    return {"status": "healthy"}

# Metrics endpoint
@app.get("/metrics")
async def metrics():
    return generate_latest()

# Example handler with metrics
@app.post("/chat/messages")
async def chat_handler(message: dict):
    # Start timer
    with response_time.time():
        # Call LLM
        response = await call_llm(message)
        
        # Record response
        chatbot_responses.labels(status="success", channel=message.get("channel")).inc()
        
        # Record tool calls
        if message.get("tools_called"):
            for tool in message["tools_called"]:
                tool_calls.labels(
                    tool_name=tool["name"],
                    result=tool.get("status", "success")
                ).inc()
    
    return response

Logging with Python

# Structured logging setup
import logging
from datetime import datetime
import json

# Configure root logger
logging.basicConfig(
    level=logging.INFO,
    format="%(asctime)s - %(name)s - %(levelname)s - %(message)s"
)

# Custom JSON formatter
class JSONFormatter(logging.Formatter):
    def format(self, record):
        log_dict = {
            "timestamp": datetime.utcnow().isoformat() + "Z",
            "logger": record.name,
            "level": record.levelname,
            "message": record.getMessage(),
            "module": record.module,
            "function": record.funcName,
            "line": record.lineno
        }
        # Add custom fields if using extra
        if hasattr(record, "tenant_id"):
            log_dict["tenant_id"] = record.tenant_id
        if hasattr(record, "user_id"):
            log_dict["user_id"] = record.user_id
        return json.dumps(log_dict)

# Set up logger
logger = logging.getLogger("sc_chatbot")
logger.setLevel(logging.INFO)
handler = logging.StreamHandler()
handler.setFormatter(JSONFormatter())
logger.addHandler(handler)

# Example usage
logger.info("Chatbot initialized", extra={"tenant_id": "tenant_123"})
logger.warning("Rate limit approaching", extra={"tenant_id": "tenant_123", "requests_remaining": 10})

Alerting Setup

Alert Rules

Configure alerts to notify about issues:

# Example alert rules (alertmanager.yml or Prometheus config)

groups:
  - name: chatbot-alerts
    rules:
      # High error rate
      - alert: HighErrorRate
        expr: rate(http_requests_total[5m]) / sum(rate(http_requests_total[5m])) > 0.05
        for: 5m
        labels:
          severity: warning
        annotations:
          summary: "High error rate detected"
          description: "Error rate is {{ $value }}% for the last 5 minutes"
          
      # Slow response times
      - alert: SlowResponses
        expr: histogram_quantile(0.95, rate(http_request_duration_seconds_bucket[5m])) > 2
        for: 5m
        labels:
          severity: warning
        annotations:
          summary: "Slow response times"
          description: "p95 response time is {{ $value }}s"
          
      # LLM API failures
      - alert: LLMAPIErrors
        expr: rate(llm_api_errors_total[5m]) > 0.1
        for: 2m
        labels:
          severity: critical
        annotations:
          summary: "LLM API errors detected"
          description: "LLM API is experiencing errors"
          
      # Rate limit exceeded
      - alert: RateLimitExceeded
        expr: rate(rate_limit_rejected_total[5m]) > 0
        for: 1m
        labels:
          severity: warning
        annotations:
          summary: "Rate limits being hit"
          description: "Clients are hitting rate limits"

Tracing with OpenTelemetry

Track requests across services and identify bottlenecks:

Tracing Example

# Install OpenTelemetry
pip install opentelemetry-api opentelemetry-sdk opentelemetry-exporter-otlp

# Initialize tracer
from opentelemetry import trace
from opentelemetry.trace import set_tracer_provider
from opentelemetry.sdk.trace import TracerProvider
from opentelemetry.sdk.trace.export import BatchSpanProcessor
from opentelemetry.exporter.otlp.proto.grpc.trace_exporter import OTLPSpanExporter

# Setup tracing
provider = TracerProvider()
processor = BatchSpanProcessor(OTLPSpanExporter())
provider.add_span_processor(processor)
set_tracer_provider(provider)

# Create tracer
tracer = trace.get_tracer(__name__)

# Use in chat handler
@app.post("/chat/messages")
async def chat_handler(message: dict):
    with tracer.start_as_current_span("chat_request") as span:
        span.set_attributes({
            "tenant_id": message.get("tenant_id"),
            "message_length": len(message.get("message", ""))
        })
        
        # Call downstream services
        response = await call_llm(message)
        
    return response

Monitoring Checklist

  • Health endpoint: /health returns system status
  • Metrics endpoint: /metrics exposes Prometheus format
  • Structured logs: JSON format with consistent fields
  • Distributed tracing: Track requests end-to-end
  • Alerting: Notify on errors and performance issues
  • Dashboard: Visual overview in Grafana
  • Log aggregation: Centralize logs with ELK or Loki
💡 Tip: Start simple with Prometheus metrics. Add Grafana and tracing as you need them. Don't over-monitor in POC phase.
