Overview

This guide covers deploying the SC Chatbot platform using Docker containers. The platform is designed for rapid deployment across development, testing, and production environments.

💡 The Docker Compose setup is perfect for POC and MVP phases. For production scale, consider Kubernetes or systemd services with .deb/.rpm packages.

POC Ready

Quick Start with Docker Compose

Prerequisites

  • Docker Engine 20.10+
  • Docker Compose v2+
  • Python 3.11+ (for local development)
  • 4GB RAM minimum (8GB recommended)

Step 1: Clone and Setup

# Clone repository
git clone https://github.com/di-hieu/e-business.git
cd e-business

# Create virtual environment
python3 -m venv venv
source venv/bin/activate

# Install Python dependencies
pip install -r requirements.txt

# Create .env file (see .env.example)

Step 2: Run with Docker Compose

# Build and start containers
docker compose up -d --build

# View logs
docker compose logs -f backend

# Stop containers
docker compose down

Step 3: Access the Application

  • Backend API: http://localhost:8000/docs (Swagger UI)
  • Frontend: http://localhost:3000

Docker Compose Structure

Docker Compose Configuration

version: '3.8'

services:
  # Backend API Service
  backend:
    build:
      context: ../src/backend
      dockerfile: Dockerfile
    container_name: sc-chatbot-backend
    ports:
      - "8000:8000"
    environment:
      - PYTHONUNBUFFERED=1
      - DATABASE_URL=sqlite:///./data/chatbot.db
      - FAISS_DIR=/app/data/faiss
      - OPENAI_API_KEY=${OPENAI_API_KEY}
      - LITELLM_MODELS=${LITELLM_MODELS}
    volumes:
      - ./data:/app/data
      - ./logs:/app/logs
    restart: unless-stopped
    healthcheck:
      test: ["CMD", "curl", "-f", "http://localhost:8000/health"]
      interval: 30s
      timeout: 10s
      retries: 3

  # Frontend Application
  frontend:
    build:
      context: ../src/frontend
      dockerfile: Dockerfile
    container_name: sc-chatbot-frontend
    ports:
      - "3000:3000"
    depends_on:
      - backend
    restart: unless-stopped

  # Redis for caching (optional for MVP)
  redis:
    image: redis:7-alpine
    container_name: sc-chatbot-redis
    ports:
      - "6379:6379"
    volumes:
      - ./data/redis:/data
    restart: unless-stopped
ServicePortDescription
backend8000FastAPI backend service
frontend3000React frontend application
redis6379Cache storage (optional)

Creating a Dockerfile

Backend Dockerfile

# Use official Python image
FROM python:3.11-slim

# Set environment variables
ENV PYTHONUNBUFFERED=1
ENV PYTHONDONTWRITEBYTECODE=1

# Install system dependencies
RUN apt-get update && apt-get install -y \
    git \
    curl \
    && rm -rf /var/lib/apt/lists/*

# Set working directory
WORKDIR /app

# Copy requirements first (cache optimization)
COPY requirements.txt ./
RUN pip install --no-cache-dir -r requirements.txt

# Copy application code
COPY . .

# Create directories
RUN mkdir -p data/faiss logs

# Expose port
EXPOSE 8000

# Run with uvicorn
CMD ["uvicorn", "main:app", "--host", "0.0.0.0", "--port", "8000", "--workers", "1"]

Frontend Dockerfile

# Build stage
FROM node:18-alpine as builder

WORKDIR /app
COPY package*.json ./
RUN npm ci
COPY . .
RUN npm run build

# Production stage
FROM nginx:alpine

# Copy built files
COPY --from=builder /app/dist /usr/share/nginx/html

# Copy nginx config
COPY nginx.conf /etc/nginx/conf.d/default.conf

EXPOSE 3000

CMD ["nginx", "-g", "daemon off;"]

Systemd Service (Production)

After Packaging with fpm

For on-premises deployment, the platform can be installed as a systemd service after creating .deb/.rpm packages.

Backend Service Unit

# /etc/systemd/system/sc-chatbot-backend.service
[Unit]
Description=SC Chatbot Backend API
After=network.target redis.service

[Service]
Type=notify
User=sc-chatbot
Group=sc-chatbot
ExecStart=/usr/bin/python /opt/sc-chatbot/venv/bin/uvicorn main:app \
    --host 127.0.0.1 \
    --port 8000 \
    --workers 4 \
    --log-level info
Restart=on-failure
RestartSec=10s

# Environment
Environment="OPENAI_API_KEY=..."
Environment="DATABASE_URL=sqlite:///..."
Environment="FAISS_DIR=/app/data/faiss"

# Security
NoNewPrivileges=true
ProtectSystem=strict
ProtectHome=true
PrivateTmp=true

[Install]
WantedBy=multi-user.target

# /etc/systemd/system/sc-chatbot-crawler.service

Manage Services

# Enable and start all services
sudo systemctl enable sc-chatbot-backend
sudo systemctl enable sc-chatbot-crawler
sudo systemctl enable sc-chatbot-admin

# Start services
sudo systemctl start sc-chatbot-backend
sudo systemctl start sc-chatbot-crawler
sudo systemctl start sc-chatbot-admin

# Check status
sudo systemctl status sc-chatbot-backend

# Stop services
sudo systemctl stop sc-chatbot-backend

# Restart services
sudo systemctl restart sc-chatbot-backend

Backup and Restore

Backup Database and FAISS Indexes

# Backup SQLite database
tar -czf backup-$(date +%Y%m%d).tar.gz \
    data/chatbot.db \
    data/faiss/*.faiss

# Backup to cloud storage
aws s3 cp backup-*.tar.gz s3://my-bucket/backups/

# Restore from backup
tar -xzf backup-$(date +%Y%m%d).tar.gz -C /path/to/data

Automated Backup with Cron

# Add to crontab
0 2 * * * /opt/sc-chatbot/scripts/backup-database.sh

# backup-database.sh content:
#!/bin/bash
BACKUP_DIR=/backups
DATE=$(date +%Y%m%d_%H%M%S)
tar -czf $BACKUP_DIR/backup-$DATE.tar.gz \
    /data/chatbot.db \
    /data/faiss/*.faiss
gzip -f $BACKUP_DIR/backup-$DATE.tar.gz
# Keep only last 30 days
find $BACKUP_DIR -name "*.tar.gz" -mtime +30 -delete

Monitoring and Logging

View Docker Logs

# View all logs
docker compose logs -f

# View specific service logs
docker compose logs -f backend
docker compose logs -f frontend

# Tail last 100 lines
docker compose logs --tail=100 backend

# Follow logs with grep
docker compose logs -f backend | grep ERROR

Health Checks

# Check backend health
curl http://localhost:8000/health

# Check if container is healthy
docker compose ps

# Get health status
docker inspect --format='{{.State.Health.Status}}' sc-chatbot-backend

Production Considerations

AspectRecommendation
SecurityUse Docker secrets for sensitive data, run as non-root user
NetworkingUse Docker Networks for container isolation
ScalingUse Kubernetes or ECS for horizontal scaling
Resource LimitsSet memory/CPU limits to prevent container resource exhaustion
Auto-restartSet restart policies for production deployments

Resource Limits Example

backend:
  deploy:
    resources:
      limits:
        cpus: 1
        memory: 2G
  mem_limit: 2g
  cpus: 1

Multi-Tenant Deployment

Isolated Docker Compose per Tenant

# Tenant-specific configuration
cp .env.example .env
sed -i "s/TENANT_ID=.*/TENANT_ID=tenant_123/" .env

docker compose up -d --build

# For on-prem, create systemd override
systemctl create-sc-chatbot-backend@tenant_123.service
