🎯 Testing Phases Overview

Detailed breakdown of E2E testing for each development phase

📋 Phase 1: POC Testing E2E

Duration: Month 1-3
Goal: Validate core functionality
Test Type: Functional + Unit

Epic 1.1: Channel Integration Tests E2E

  • Zalo Integration Tests:
    • Webhook signature verification (HMAC-SHA256)
    • Message parsing (text, image, audio)
    • Template message support
    • Rate limiting (60 msg/min per OA)
    • Error handling for invalid payloads
  • Facebook Messenger Tests:
    • Webhook verification (X-Hub-Signature)
    • Quick reply handling
    • Template message generation
    • Persistent menu configuration
    • File attachment support
  • Instagram Direct Tests:
    • Graph API webhook handling
    • Story reply support
    • Product tag messages
    • Carousel media handling
    • User verification flow

Epic 1.2: RAG Pipeline Tests Integration

  • Embedding Generation Tests:
    • all-MiniLM-L6-v2 quality verification
    • 384-dimensional vector output
    • Batch embedding generation
  • Vector Search Tests:
    • FAISS similarity search accuracy
    • K-nearest neighbor retrieval
    • Metadata filtering support
  • Context Injection Tests:
    • Prompt formatting with retrieved docs
    • Truncation for long contexts
    • Source attribution in responses
  • Response Generation Tests:
    • GPT-4o-mini response quality
    • Streaming response support
    • Fallback to general responses

Epic 1.3: Tool Calling Tests Integration

  • Tool Definition Tests:
    • JSON Schema validation
    • Endpoint availability checks
    • Method (GET/POST/PUT) validation
  • Parameter Extraction Tests:
    • LLM asks for missing parameters
    • Multi-turn parameter collection
    • User-friendly prompts
  • Error Handling Tests:
    • Unknown tool handling
    • Invalid parameter validation
    • Rate limiting enforcement

Epic 1.4: Basic Admin Dashboard Tests E2E

  • Login/Logout Tests:
    • JWT authentication
    • Password reset flow
    • Session timeout handling
  • Knowledge Upload Tests:
    • PDF file upload
    • Text content paste
    • CSV upload
    • Validation of file types
  • Tool Management Tests:
    • Tool definition creation
    • Schema editing
    • Test button functionality
  • Conversation Viewer Tests:
    • Real-time message streaming
    • Conversation search
    • Export to CSV/JSON

🎉 Phase 1 Success Criteria

  • ✅ Zalo webhook integration working

🛠️ Testing Tools & Technologies

Technology stack for comprehensive testing

Pytest

Python testing framework. Industry standard, async support (pytest-asyncio), rich plugin ecosystem (pytest-html, pytest-xdist).

Playwright

Cross-browser E2E testing. Supports Chrome, Firefox, WebKit. Automated UI interactions, screenshots, network monitoring.

Locust

Python-based load testing. Scripted in Python, real-time graphs, distributed test execution, concurrent user simulation.

Snyk

Security vulnerability scanning. Dependency CVE detection, container image scanning, security advisory management.

Coverage.py

Python code coverage tool. Line/function/branch coverage, HTML reports, integration with pytest.

Allure

Beautiful test reporting. Cross-platform, interactive dashboards, historical trend analysis, CI/CD integration.

⚠️ Testing Challenges & Solutions

  • LLM Response Variability: Use LLM response verification that focuses on structure, not exact text
  • Webhook Rate Limits: Implement exponential backoff in tests; use mock servers
  • Browser Compatibility: Test on multiple browsers (Chrome, Firefox, Safari)
  • Environment Parity: Use docker-compose for test environment mirroring production
  • Data Privacy: Never store real user data in test fixtures; use anonymized data
  • Test Flakiness: Isolate tests that fail intermittently; investigate root cause

📝 Running Tests

How to execute different test suites

# Run all tests
pytest test/ -v

# Run E2E tests only
pytest test/ -m e2e -v

# Run specific test file
pytest test/channels/test_zalo_channel.py -v

# Run tests with coverage report
pytest test/ -v --cov=src/backend --cov-report=html

# Run load tests
pytest test/load/ -v --locust

# Generate HTML report
pytest test/ --html=report.html --self-contained-html

# Run only failing tests
pytest test/ -v --ff

# Run tests for specific channel
pytest test/channels/ -v -m "e2e and channel"

# Continuous Integration (GitHub Actions)
pytest test/ -v --junit-xml=pytest-junit.xml --cov=src/backend
