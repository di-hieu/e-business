Overview

Function Calling enables the chatbot to perform actions beyond simple conversation. Admins define custom tools (API endpoints), and the LLM decides when to call them based on user queries. This capability transforms the chatbot from a passive responder to an active assistant.

Planned

What is Function Calling?

Function Calling (also known as Tool Calling) is an LLM capability where the model can:

  1. Identify when a user query requires an external action
  2. Select the appropriate tool to call
  3. Construct the correct parameters for the tool
  4. Execute the tool call via API
  5. Present the result to the user in natural language

Example Flow

1
User Query

"What's the price of product SKU123?"

2
LLM Analysis

LLM recognizes this requires checking inventory/pricing → calls check_inventory(SKU="SKU123")

3
Tool Execution

API returns: {"product": "Widget Pro", "price": "$49.99", "stock": 50}

4
Final Response

LLM formats: "The Widget Pro costs $49.99 and we have 50 units in stock."

Tool Definition Framework

Admins define tools via the admin dashboard or API. Each tool needs:

  • name: Unique identifier (e.g., check_inventory, track_order)
  • description: What the tool does (guides LLM when to use it)
  • parameters: JSON Schema defining input structure
  • endpoint: API URL where tool is exposed
  • auth: Authentication method (API key, OAuth, etc.)

Defining Tools via API

Register a Tool

# Register new tool
curl -X POST http://localhost:8000/api/tenants/tenant123/tools \
  -H "Authorization: Bearer TENANT_ADMIN_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "tool_id": "check_stock",
    "name": "check_stock",
    "description": "Check stock levels for specific product",
    "parameters": {
      "type": "object",
      "properties": {
        "product_id": {
          "type": "string",
          "description": "Product identifier"
        },
        "warehouse": {
          "type": "string",
          "description": "Warehouse location"
        }
      },
      "required": ["product_id", "warehouse"]
    },
    "endpoint": "https://oms.example.com/api/v1/inventory/stock",
    "method": "GET",
    "auth_header": "X-API-Key",
    "auth_value": "{{OMS_API_KEY}}"
  }'

# Response
{
    "tool_id": "check_stock",
    "status": "active",
    "created_at": "2024-01-15T10:30:00Z"
}

Parameter Extraction

The LLM needs to extract the right parameters from user queries. This requires clear descriptions in the tool schema.

Parameter Examples

# Good parameter descriptions
{
  "parameters": {
    "properties": {
      "order_id": {
        "type": "string",
        "description": "Customer order number (e.g., ORD-12345)"
      }
    }
  }
}

# Bad parameter descriptions
{
  "parameters": {
    "properties": {
      "id": {
        "type": "string"
      }
    }
  }
}

# The first version helps the LLM understand the expected format.

Handling Missing Parameters

When a user query lacks required parameters, the LLM should ask clarifying questions:

1
User Query

"Check my order"

2
LLM Response

"Could you please provide your order number? For example: ORD-12345"

3
User Response

"ORD-67890"

4
Tool Execution

LLM now calls track_order(order_id="ORD-67890")

Tool Execution Flow

Here's how the system executes a tool call:

1
User Message Received

User asks: "How much does the iPhone 15 cost in Vietnam?"

2
Tool Selection

LLM identifies check_product_price is relevant → selects it from available tools

3
Parameter Extraction

LLM extracts: {"product": "iPhone 15", "country": "Vietnam"} from query

4
API Call

System calls: GET https://api.example.com/products/price?product=iphone15&country=vn

5
Response Processing

API returns: {"price": "$49.99", "currency": "USD", "tax_included": true}

6
Final Response

LLM formats: "The iPhone 15 in Vietnam costs $49.99 USD (tax included)"

Tool Calling with LangChain

Here's how to implement tools using LangChain:

Create a Tool Class

# LangChain Tool wrapper
from langchain.tools import tool

@tool
def check_inventory(sku: str, region: str) -> dict:
    """Check product availability and pricing.
    
    Args:
        sku: Product SKU identifier
        region: Target region (VN, US, EU, APAC)
    
    Returns:
        Product information including price and stock
    """
    # Call external API
    response = requests.get(
        f"https://api.example.com/inventory/{sku}",
        headers={"X-API-Key": os.getenv("OMS_API_KEY")},
        params={"region": region}
    )
    
    return {
        "product": response.json()["product_name"],
        "price": response.json()["price"],
        "stock": response.json()["available_quantity"],
        "region": region
    }

# Register with LangGraph
tools = [check_inventory]

# Use in LangChain agent
from langgraph.graph import StateGraph
from langchain_core.messages import BaseMessage

graph = StateGraph(state_schema)
graph.add_node("tools", execute_tool(tools))
graph.add_edge("start", "tools")

app = graph.compile()

Tool Calling Best Practices

Description Quality

  • Use specific, descriptive names (not generic like "get_info")
  • Include examples in parameter descriptions
  • Be explicit about what the tool returns

Error Handling

# Handle API errors gracefully
@tool
def check_inventory(sku: str, region: str) -> dict:
    try:
        response = requests.get(url, ...)
        return {"product": ..., "error": None}
    except requests.exceptions.HTTPError as e:
        return {"product": "Unknown", "error": f"API error: {e}"}
    except Exception as e:
        return {"product": "Unknown", "error": str(e)}

Rate Limiting

Implement rate limiting on external API calls to avoid hitting quotas:

# Add retry logic with exponential backoff
import time
from tenacity import retry, stop_after_attempt, wait_exponential

@retry(stop=stop_after_attempt(3), wait=wait_exponential(multiplier=1, min=4, max=10))
def call_api_with_retry(url: str, **kwargs) -> dict:
    response = requests.get(url, **kwargs)
    response.raise_for_status()
    return response.json()
