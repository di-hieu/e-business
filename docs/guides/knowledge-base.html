Overview

The knowledge base is the core of the SC Chatbot's AI capabilities. It stores documents, FAQs, and product information that the chatbot uses to generate context-aware responses using RAG (Retrieval-Augmented Generation).

Planned

What is a Knowledge Base?

A knowledge base is a structured collection of information that the chatbot can access and use to answer user queries. The system processes this information using RAG to provide accurate, fact-based responses.

RAG Pipeline Overview

The RAG (Retrieval-Augmented Generation) pipeline enables the chatbot to answer questions from your knowledge base without retraining the model.

How RAG Works

1
Chunking

Documents are split into ~300-token chunks with 50-token overlap. Each chunk becomes a searchable unit.

2
Embedding

Each chunk is converted to a 384-dimensional vector using the embedding model (all-MiniLM-L6-v2 in POC, OpenAI text-embedding-3-small in production).

3
Storage

Vector embeddings are stored in FAISS (POC) or Qdrant (production), indexed for fast similarity search.

4
Retrieval

When a user asks a question, it's embedded and used to search for the most similar chunks (top-k).

5
Generation

Retrieved chunks are injected into the LLM prompt as context, and the model generates a grounded response.

Document Chunking Strategy

Chunking is critical for RAG performance. The system splits documents into manageable pieces while preserving context.

Chunk Size Options

Chunk SizeOverlapBest For
200 tokens20 tokensShort documents, FAQs
300 tokens50 tokensGeneral use (default)
500 tokens100 tokensLong articles, manuals

Semantic Chunking

Advanced chunking uses sentence boundaries and semantic similarity to create more coherent chunks:

# Semantic chunking with sentence splits
from langchain.text_splitter import RecursiveCharacterTextSplitter

text_splitter = RecursiveCharacterTextSplitter(
    chunk_size=300,
    chunk_overlap=50,
    separators=["\n\n", "\n", " ", ""],
    length_function=len
)

chunks = text_splitter.split_text(documents)

Upload Documents

Via Admin Dashboard

  1. Navigate to Knowledge Base section
  2. Click "Upload Document"
  3. Select file (PDF, CSV, TXT)
  4. Choose source name and chunk settings
  5. Click "Upload"
  6. Wait for processing (embeddings are generated)

Via API

# Upload single file
curl -X POST http://localhost:8000/api/tenants/tenant123/knowledge/upload \
  -H "Authorization: Bearer TENANT_API_KEY" \
  -F "file=@faq.pdf" \
  -F "source=documentation" \
  -F "chunk_size=300" \
  -F "chunk_overlap=50"

# Response
{
    "document_id": "doc_abc123",
    "source": "documentation",
    "status": "processing",
    "chunks_created": 45,
    "created_at": "2024-01-15T10:30:00Z"
}

Upload Multiple Files

# Upload batch via API
curl -X POST http://localhost:8000/api/tenants/tenant123/knowledge/import \
  -H "Authorization: Bearer TENANT_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "documents": [
      {
        "source": "product-catalog",
        "file": "@catalog.xlsx",
        "chunk_size": 200
      },
      {
        "source": "faq",
        "text": "Q: How do I reset my password?\\nA: Go to settings...",
        "chunk_size": 200
      }
    ]
  }'

Web Crawler (Planned)

The system can automatically crawl websites to extract content. This is useful for keeping product information up-to-date without manual uploads.

Crawler Configuration

# Crawler settings
curl -X POST http://localhost:8000/api/tenants/tenant123/crawler/config \
  -H "Authorization: Bearer TENANT_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "url": "https://example.com/products",
    "selector": ".product-card",
    "interval": "daily",
    "max_pages": 100,
    "exclude_patterns": ["/admin", "/login"]
  }'

Embedding Model Options

POC: all-MiniLM-L6-v2

Pros: Free, runs locally, ~50MB size
Cons: Smaller than OpenAI embeddings, slower

Production: OpenAI text-embedding-3-small

Pros: Higher quality, faster cloud inference
Cons: Per-token cost (~$0.02/1k tokens)

Alternative: BGE

Pros: Excellent for Chinese languages
Cons: Larger file size

RAG Optimization Tips

Chunk Size Tuning

  • Smaller chunks (200): Better precision for specific questions
  • Larger chunks (500+): Better context preservation

Similarity Threshold

# Adjust minimum similarity score
min_similarity = 0.7  # Default

# For stricter filtering
min_similarity = 0.85

# For more lenient (broader context)
min_similarity = 0.5

Top-k Retrieval

  • k=3: Focused, concise responses
  • k=5: Balanced (recommended)
  • k=10: Broader context, longer responses

Knowledge Base Best Practices

Document Quality

  • Clear formatting: Use proper headers and paragraphs
  • Concise language: Avoid unnecessary verbosity
  • Accurate information: Ensure facts are up-to-date

Regular Updates

  • Review and update knowledge monthly
  • Remove outdated documents
  • Add new product information promptly
